# V3.4 / V3.5 — Fixture research and bounded commands

Started 2026-10-18. This document precedes implementation edits.

## Admission and authority design

Preserve the existing queue, spawned worker, dispatcher, ledger, permits, Stop,
checkpoint store and native gates. Browser admission initially supports only a
bundled loopback fixture scope. The server owns its fixture site, paths, redirects,
browser binary, ephemeral session and network policy; clients choose bounded
source IDs, a source count and a new JSON basename. No arbitrary URL, local port,
executable, profile directory, selector, upload or approval flag is accepted.

Qualification must precede registration. Fixture support does not qualify public
web research. Source observations and hashes prove observed content and artifact
integrity, not the truth of page text or model-generated claims. Page content is
untrusted data and never grants tool/approval authority.

Text command intake persists a protected intent and stable clarification identity
before any effect. Missing/ambiguous fields ask for bounded typed clarification.
An atomic stored transition and the existing request-ID task mapping connect a
completed intent to one queued task, including after an uncertain response/restart.
No command is submitted on page refresh. Expired or interrupted intake requires
fresh explicit review and never automatically replays an effect.

One internal command wrapper runs the existing bounded LangGraph inside the
existing owner worker. Its catalog contains only the selected admitted workflow;
validators bind the exact confirmed arguments. Deterministic requests use the
existing router; optional local reasoning uses the strict parser/GatewayPlanner
with an actual server-pinned model and finite persistent budgets. Neither a model
finish nor a wrapper return establishes completion without ledger and artifact proof.
Native Save keeps its V3.2 human-review boundary. No second scheduler or automatic
cloud fallback is introduced.

## Implemented behavior

- `POST /api/workflows/browser-research` accepts only `source_ids`,
  `required_sources` and a new `.json` basename. `source-a`, `source-b` and
  `redirect-a` refer to server-owned bundled fixtures. The last ID redirects to
  source A and cannot count as a second distinct source. Generic task submissions
  enforce the same admission gate. A removed browser prerequisite blocks admission.
- The server owns the loopback fixture site and ephemeral Chromium context. Only
  reviewed GET document URLs, their reviewed redirect and the exact loopback
  address are permitted. Existing session ownership, transfer/popup restrictions,
  target freshness, cancellation and dispatch checks remain in force.
- The workflow uses existing per-step authorization, ledger receipts and a new
  destination. The outer verifier checks successful status, required/distinct
  source counts, observation identities, reviewed URLs and source text hashes.
  The inner Save verifier checks exact report bytes. Extracted source text and
  its deterministic extractive summary do **not** establish claim truth.
- `POST /api/commands` requires a stable `X-Client-Request-ID`; `GET
  /api/commands/{command_id}` is read-only; `POST /api/commands/{command_id}/clarify`
  explicitly continues an intake. Requests cannot supply tools or approval flags.
  Known values cannot be replaced during clarification. Concurrent resume and a
  crash after durable queue commit resolve to the existing task mapping.
- Intake is protected at rest, expires after 300 seconds and is limited to 128
  outstanding clarifications. A service session admits at most 128 internal
  command tools. Cleanup expires payloads; forgetting purges linked command text;
  retention removes old intake mappings with their tasks. Restore invalidates
  unsubmitted intakes. Startup never automatically submits clarification or
  repeats an interrupted command.
- Each confirmed command runs the existing graph inside the existing queued
  mutation worker. The exact selected workflow is its entire tool catalog. Model
  changes to its tool, payload or destination fail validation. Independent ledger,
  content-hash and workflow verification are required before reporting success.
  The graph allows 32 nodes, one workflow action, four observations, two model
  requests, 1,024 reserved output tokens and 60 active seconds; the outer worker
  has a 120-second limit. Existing checkpoint/budget and Stop handling are reused.
- The dashboard accepts text, displays missing values and an opaque saved command
  ID, and provides an explicit read-only lookup after refresh. It retains the
  same pending payload and identity after uncertain transport. Refresh never
  submits work. Existing task events, approval panel and Stop remain shared.

Supported explicit templates (quoted content and item arrays use JSON syntax):

```text
Create a note hello.txt containing "Hello VICTUS"
Create checklist study.txt with items ["Read", "Practice"]
Research sources source-a, source-b into research.json
```

An incomplete request such as `Create a note` asks for filename and literal text.
Ambiguous multi-domain requests ask for an explicit task type. This is bounded
intent intake, not unrestricted desktop or shell instruction execution.

## Qualification and current availability

The note command is implemented and verified through queue, spawned worker,
graph and exact file checks with controlled unit-test telemetry. Native checklist
commands remain disabled by the existing V3.1 qualification failure; V3.2 approval
authority is preserved and cannot be supplied by a command client.

Fixture research wiring is implemented but **not enabled**. Three fresh live
attempts were refused at admission by the unchanged production memory guard.

`admission_sources.json` with `RESOURCE_PRESSURE`; available physical memory at
the recorded boundary was 1,197,588,480 bytes, below the 2 GiB requirement. No
browser workflow ran in that attempt. Chromium 1248 and Playwright 1.64.0 were
observed; their presence does not qualify the workflow. No
`fixture-qualification.json` was promoted. Registration requires a trusted record
matching the fixture hash, installed Playwright version and actual browser hash.
No public-web scope is enabled or qualified.

and the default model cache exposed only the `nomic-embed-text:latest` embedding
manifest. No installed reasoning pin was established and none was invented.

installed local model before the optional reasoning path can be admitted; the
server checks the live name/digest. These settings were left unset. No model was
downloaded, loaded or sent to a cloud service.
