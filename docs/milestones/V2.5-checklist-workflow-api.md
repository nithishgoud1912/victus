## Planned files and contracts

Inspect/extend `workflows/create_notepad_checklist.py`, `workflows/common.py`,
`tools/desktop.py`, existing safety approvals/permits, payloads/ledger and tests.
Add a strict workflow transport and `api/routes/workflows.py`, connect it to task
service admission and the existing authenticated API. No arbitrary profile paths,
roots, selectors, executables or approval flags enter the transport. Use trusted
server capability registration; production provides no qualified native profile
until the live gates pass. Tests use an explicit fake adapter, never native UI.

Input: supported profile ID, bounded single-line checklist items, new workspace
basename and existing request-ID header. Output: HTTP 202 task identity on admitted
qualified capability, or clear validation/dependency failure before admission.
Task lookup/events/Stop remain the existing control plane. Native approval review
integration must pass target/payload/expiry binding before native registration.

## Exact files changed

- [create_notepad_checklist.py](../../backend/victus/workflows/create_notepad_checklist.py):
  check the permit's path against the request's exact basename; propagate the
  existing cancellation signal into local handlers and check it again immediately
  before Save; require the editor to remain actionable and unchanged as well as
  exact output bytes before accepting save success.
- [contracts.py](../../backend/victus/workflows/contracts.py): strict profile/items/
  basename transport, existing checklist text bounds and explicit unavailable state.
- [workflows.py](../../backend/victus/api/routes/workflows.py) and
  [app.py](../../backend/victus/api/app.py): authenticated narrow endpoint, HTTP
  202 task identity or clear 422/429/503 before native admission; existing auth,
  origin restrictions, approval routes, events, task lookup and Stop preserved.
- [service.py](../../backend/victus/tasks/service.py): trusted supported-profile
  gate for both narrow and generic task routes; delegate to the same queue. No
  native tool is registered by bootstrap and no client can supply qualification.
- [queue.py](../../backend/victus/tasks/queue.py): optional trusted pre-admission
  check inside the existing admission lock, after duplicate lookup and before
  persistence. A replay after file creation still returns the original task.
- [test_notepad_workflow.py](../../backend/tests/test_notepad_workflow.py): preserve
  the existing simulated workflow and add permit/path/modal/Stop effect checks.
- [test_workflow_api.py](../../backend/tests/test_workflow_api.py): 30 narrow API
  contracts using simulated UIA, including concurrent deduplication and prevention
  of generic-route profile-gate bypass.
- `dashboard/openapi.json` and generated `dashboard/src/api/generated/` contracts:
  regenerated from the current server; no new native workflow UI is enabled.
- This document, [decision 006](../decisions/006-gated-checklist-admission.md),
  [V2 progress](V2-progress.md), [workflow matrix](../supported-workflows.md) and
  [sanitized evidence](../release/v2.5-workflow-evidence.json).

No second dispatcher, approval database, broad desktop registration or schema
migration was added. Existing approval stores and the target/policy/payload-bound
single-use permit implementation pass their tests. Wiring a native HTTP workflow
through that review path is still pending and is a prerequisite for registration;
the reviewed context in local qualification and fake tests does not authorize HTTP.
