# V2.3 - Stop, supervision and resource ownership

## Objective and prior working state - 2026-10-18

Verify that Stop independently latches cancellation, drains pending tasks and
signals owned spawned workers; native hangs must meet finite deadlines and be
reaped before mutation or runtime-directory ownership is released. Partial
effects remain possible/unknown, never reported as undone. A shortcut fixture is
separate from a deliberate physical key test. This record precedes V2.3
production edits.

Base revision: `64a0a22127a2d450a8d8bb4047cf76cae0cc4995`, preserving existing
uncommitted V2.1/V2.2 changes. V2.2 qualified 659 backend tests, 42 focused
storage/queue checks, 20 frontend tests and a real source dashboard note check.
Qualification runtime roots remain isolated beneath `.local/`; personal runtime
data, credentials and `.env` content are excluded.

## Inspection and intended changes

Already present: cancellation launch barrier, process-shared mutation ownership,
Windows spawn with top-level worker/adapters, cooperative cancellation followed
by terminate/kill of the owned child only, process join before normal return,
instance-directory OS lock, opt-in shortcut using Services.stop, conservative
unknown outcomes for native partial effects and Stop rechecks before dispatch.

Gaps to verify/fix: failed reaping can release the mutation slot even though the
worker handle is retained; shutdown currently performs optional cleanup before
latching task Stop, so an optional cleanup failure can skip worker shutdown;
mutation-slot waiting in the task queue is not bounded by its operation budget;
and Stop must be checked again after durable dispatch-intent I/O and before the
adapter is invoked. Also qualify partial worker-launch failure ownership.

Exact production files changed: `backend/victus/runtime/supervisor.py`,
`backend/victus/runtime/instance_lock.py`, `backend/victus/tasks/queue.py`,
`backend/victus/tools/dispatcher.py`, and `backend/victus/bootstrap.py`.
Tests: `backend/tests/test_supervisor.py` and `backend/tests/test_hotkey.py`.
Documentation: this record, `docs/milestones/V2-progress.md`,
`docs/supported-workflows.md`, `docs/decisions/004-stop-and-owner-retention.md`
and `docs/release/v2.3-stop-evidence.json`. Cancellation, mutation-lock wiring,
shortcut production code and native UIA owner implementation were inspected and
retained; existing instance-lock ownership was extended for failed cleanup.

Inputs: strict serialized request, registered importable adapter, trusted worker
authority, finite deadline and Stop signal. Outputs: verified success or bounded
failed/cancelled/unknown result; unreapable ownership is retained and surfaces a
shutdown error. No cancellation path promises rollback of text or saved files.

## Verification plan

Extend `test_supervisor.py` and `test_hotkey.py`: blocked native fake, deadline,
abrupt child exit, queued Stop, dispatch-boundary Stop, cooperative-before-forced
exit, slot retention when reap fails, runtime-lock retention and cleanup faults.
Use real spawned test workers for native lifecycle proofs and deterministic
fakes for an unkillable process; never deliberately leave a real worker alive.
Run focused and full backend suites with `.local/` basetemp/XML, then dashboard
regression and source UI check as appropriate. Physical Ctrl+Alt+Pause remains
pending unless the human deliberately tests it; synthetic key injection is not
physical-key evidence.

Manifest: `.local/v23-source.json`, on the base commit above with dirty changes.

- [TaskQueue](../../backend/victus/tasks/queue.py) gives active slot waiting and
  supervised execution one absolute deadline, and retains the slot while an
  owned worker handle remains unreaped.
- [WorkerSupervisor](../../backend/victus/runtime/supervisor.py) owns the exact
  process before start, handles partial launch, signals before reaping, and
  preserves process/mutation ownership on failed reap. Only that owned child
  receives terminate/kill, after finite cooperative and forced grace periods.
- [Dispatcher](../../backend/victus/tools/dispatcher.py) rechecks Stop/deadline
  after the durable dispatch-intent write and before calling the adapter.
- [Services](../../backend/victus/bootstrap.py) latches Stop first, attempts
  independent cleanup despite optional errors, and retains directory ownership
  if any owner has not closed safely. [InstanceLock](../../backend/victus/runtime/instance_lock.py)
  keeps a failed-cleanup handle alive through caller unwinding/garbage collection.

The [ownership decision](../decisions/004-stop-and-owner-retention.md) records
these cross-module boundaries and why partial effects are never rollback claims.
