# V3.2 / V3.3 — Owned native review and checklist dashboard

Started 2026-10-18. This lifecycle specification precedes implementation edits.
Preserve the dirty V3.1 tree, normal resource guards and unqualified native gate.

## Worker-owner lifecycle

The existing queue keeps one active task and mutation slot. Its spawned worker
retains all native process leases, COM objects and control references throughout
the workflow and review. A trusted owned-execution callback receives only the
service-assigned task/action identity, scopes and cancellation signal. The HTTP
request never supplies authority, executable paths, selectors or qualification.

After resolving the owned editor and Save dialog, the worker prepares the exact
Save action in the existing ledger and creates an existing ApprovalStore record.
Its binding covers task/action, tool/version, policy, profile, process creation,
window/control runtime identities, intended new destination/parent identity and
actual editor payload hash. Preview text is protected with the existing DPAPI
storage. Only opaque approval/action IDs cross the control plane.

The worker persists `waiting_for_review` plus an atomic task event, then polls
the approval record at finite intervals while retaining its mutation ownership.
Approval TTL and the enclosing supervised deadline bound this wait. Disconnecting
the browser changes no authority; refresh recovers approval identity in the task
snapshot. No second mutation worker enters while review is pending.

The existing authenticated approval routes approve once or deny. On approval,
the owner recomputes the binding, issues the existing single-use permit and uses
the shared dispatcher to revalidate/consume it. Save rechecks cancellation,
destination, editor, target, approval expiry and consumed authority immediately
before native Invoke, including after filename preparation. Any possible effect
without proof remains unknown and is never automatically replayed.

Denial/expiry/Stop/timeout invalidate pending authority. Worker finalization retires
any remaining review authority; queue finalization also retires it if the worker
was killed. Startup treats waiting tasks as interrupted and invalidates old
approvals/permits through existing recovery. No native objects are serialized,
no second scheduler or user-facing auto-approval flag is introduced.

Production native registration requires independently qualified native and review
evidence. V3.1 native qualification is still blocked, so bootstrap stays disabled.
Tests inject an explicit simulated adapter through trusted server wiring and must
not count as native Windows qualification.

## Implementation and exact boundaries

| Area | Files / behavior |
|---|---|
| Owned execution | `tools/registry.py` adds a trusted `execute_owned` callback; `tools/dispatcher.py` supplies service-assigned `WorkerAuthority`. Requests cannot supply this callback or authority. |
| Native review | `workflows/native_review.py` keeps the UIA worker alive, prepares the exact Save ledger action, binds identities/destination/editor hash, protects previews through ApprovalStore and reuses PermitStore consumption. |
| Save boundary | `workflows/create_notepad_checklist.py` obtains a reviewed step context for Save only. `adapters/uia/actions.py` runs a final guard after focus/reacquisition and immediately before native Invoke. Expiry, cancellation, target, editor and committed filename are rechecked there. |
| Durable task lifecycle | `tools/contracts.py` adds waiting state and approval ID; `storage/database.py` adds worker-only attachment without startup recovery. Waiting state/event writes remain atomic and do not count as terminal retention. |
| Finalization and restart | `tasks/queue.py` retires remaining authority/unfinished ledger entries after its worker is reaped. `tasks/service.py` invalidates on Stop. Existing ResumeManager handles restart; backup/retention/voice terminal checks recognize the new waiting state. No SQL migration is required for these JSON task fields. |
| Trusted capability gate | `tasks/service.py` requires both profile sets and a registered tool. `native_checklist_spec` refuses either missing qualification assertion and pins the server-configured profile file hash. Bootstrap deliberately does not register it. Existing request mappings replay before new-admission gates. |
| Read-only capability transport | `api/routes/workflows.py` exposes `/api/workflows/capabilities`, with safe unavailable reason, trusted profile IDs, Stop and pressure flags. No paths or selectors are offered for client configuration. |
| Dashboard | `commands/ChecklistForm.tsx`, `checklistInput.ts`, `CommandInput.tsx`, task workspace/result, health and approval panels. Existing API client handles typed generated contracts and memory/session auth; no second HTTP transport is introduced. |
| Evidence | `tests/test_native_http_review.py` uses the actual queue, spawned process, ledger, approvals, permits and authenticated routes with an explicitly fake UIA backend. `tests/live/v33_dashboard_contract.py` exercises headless browser fixtures. Legacy M5–M8 fixture routes include the new read-only capability response. |

The preview shows original text as literal React text with actual line breaks,
destination and encoding separately. It does not execute HTML. Approval state is
polled read-only so another tab's decision/expiry/consumption disables stale controls.
Snapshot recovery discovers approval IDs even when the corresponding approval event
is outside the reconnect cursor. Active review keeps new mutation forms disabled;
the Stop control stays available independently.

The worker wait is bounded by a maximum 60-second review TTL and the enclosing
180-second native workflow timeout. Individual native Save/verification steps retain
their existing deadlines. The local destination permit may expire earlier; that is
a conservative rejection and never grants fresh authority. A denied/stopped workflow
may already have inserted text into its owned editor, so terminal results can be
unknown rather than pretending those effects were rolled back.
